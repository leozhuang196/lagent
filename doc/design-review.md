# 系统设计审查（2026-11-03）

本轮基于本地设计方案与实现检查租户/成员权限边界、事件续传及轮次投递。不是全面安全审计。

## 已优化

### 子资源必须继承业务权限

仓储的租户过滤只解决跨租户访问，不能代替同租户的成员权限。原来 Snapshot 检查所有者，但 GetTurn/GetArtifact/GetPending 直接返回租户内记录，知道 ID 就可绕过会话权限；产物 URL 接口复用 GetArtifact，因此还涉及下载授权。

现在轮次和会话产物统一检查父会话权限。独立工作流产物检查 StartedBy；无归属产物只允许管理员或系统访问。待办允许会话所有者、指定审核人、管理员和系统读取；处理待办仍遵守指定审核人限制，未分配待办不能由任意成员处理。ListArtifacts 逐项过滤无权查看的产物。

指定审核人的权限只覆盖待办，不自动授予完整会话或产物访问权。权限在 orch 执行，各接入层复用。

### 事件流以日志补读保证恢复

原会话与工作流 SSE 实现重复，live 通道出现序号缺口时忽略 Read 的 reset/error，仍发送较新事件并推进游标，可能永久跳过事件。若最后一次通知因队列满丢失，也没有下一次事件来触发补读。

现在两个入口共用 StreamEvents：订阅先于回放，通知触发分页日志补读；缓冲过期发 stream.reset；读取、序列化或写入失败退出连接；心跳时也检查日志，覆盖末尾通知丢失。解析游标时拒绝负数和无效值。代价是通知触发时多一次日志读取，心跳每连接每 15 秒增加一次读取；大规模连接应进一步考虑共享补读或批量通知。

### 各事件总线实现遵守相同续传语义

内存版现在识别超过当前序号的旧实例游标。Redis 版在缓冲完全过期、序号计数器仍存在时也报告 reset，客户端不必等待下一次追加才能恢复；区间查询使用排他起点，避免最大 int64 游标执行 after+1 溢出。

## 尚需完成的可靠性设计

### 高优先级：数据库与队列之间的持久交接

StartTurn 依次占用会话、插入消息、插入轮次、入队。任意进程崩溃都可能留下部分记录；入队失败后，有幂等键的重试会直接返回已有轮次，未必重新投递。maybeResume 也有待办决策落库与恢复入队之间的窗口。工作流已有 sweeper，不能据此推断普通会话同样具备补偿。

建议新增持久投递记录（outbox）及轮次补偿器：同一存储事务提交业务状态和投递意图；后台至少一次投递，消费者按轮次 ID 去重并继续使用租约与 fencing。对内存、PostgreSQL、MongoDB 提供一致契约，定义事务不可用时的降级能力；不能仅靠失败后回滚解决进程崩溃。验收应包含每个写入边界的故障注入、Redis 不可用后恢复及重复投递。

本轮未引入跨仓储事务或 outbox，因此该问题仍未解决。

### 中优先级：产物列表规模

ListArtifacts 目前最多读取 1000 条后逐项授权，会增加父资源查询；不能当作完整分页接口。后续应给业务列表添加受权限约束的分页查询，或按已授权会话/工作流查询并缓存本次请求的权限结果，避免数据量增大后的漏页及重复查库。

### 中优先级：慢连接资源边界

本轮会处理写入错误，但没有给每次 SSE 写入设置独立截止时间。需要结合反向代理、HTTP 服务器配置和最大连接数，定义慢客户端断开策略与监控；全局 WriteTimeout 不宜直接覆盖长期 SSE 连接。
